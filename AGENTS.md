\# AGENTS.md — Правила проекта и режим наставника



\## Стек технологий проекта

\- \*\*Backend:\*\* Java 17+, Spring Boot 3.1.2, Spring Security 6, Spring Data JPA.

\- \*\*База данных:\*\* MySQL (не менять диалект и настройки подключения без необходимости).

\- \*\*Безопасность:\*\* Переход с сессий и Thymeleaf на Stateless JWT (Access + Refresh токены) с сохранением ролей `ADMIN` и `USER`.

\- \*\*Frontend:\*\* React (Vite), TypeScript или современный JS, Axios (с перехватчиками/interceptors для JWT), React Router.



\## Правила написания кода (Чистый код)

1\. \*\*Синтаксис Spring Boot 3.1.2:\*\* Используй только актуальный синтаксис Spring Security 6 (через `SecurityFilterChain` и лямбда-конфигурацию). Не используй устаревшие (deprecated) классы.

2\. \*\*Архитектура:\*\* Строго разделяй слои: `@RestController` (принимает и отдает только DTO, никаких Entity наружу), `@Service` (бизнес-логика), `@Repository` (работа с MySQL).

3\. \*\*Размер файлов:\*\* Максимальный размер одного файла — 300–400 строк. Декомпозируй сложные компоненты React и сервисы Java.

4\. \*\*Тестирование:\*\* На каждый новый сервис или контроллер авторизации пиши unit-тесты (JUnit 5 + Mockito).



\## Режим обучения (Обязательно для каждого ответа!)

После того как ты внесешь изменения в файлы, всегда пиши в конце краткое резюме на русском языке по следующей структуре:

1\. \*\*Что сделано:\*\* Какие файлы созданы или изменены.

2\. \*\*Как это работает (Теория простыми словами):\*\* Объясни ключевые концепции, которые ты применил (например, как работает `OncePerRequestFilter`, зачем нужен DTO или как хранится токен в React).

3\. \*\*На что обратить внимание:\*\* Укажи 1–2 места в коде, которые мне стоит открыть и изучить самостоятельно, чтобы лучше понять архитектуру.



\## Главное правило безопасности

\*\*Никогда не коммить изменения в Git и не удаляй существующие таблицы MySQL без моего прямого разрешения.\*\*
